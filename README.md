# OreHaven Globe
An interactive geographic intelligence visualization built in D3.js. The project tracks roughly 50 industrial and infrastructure nodes across North America, South America, Europe, Africa, Asia, Australia, and the Pacific, layered against live data streams: real-time USGS earthquake monitoring, NOAA weather alerts and hurricane tracks, ~90 curated global mine locations, and a conceptual continental water infrastructure overlay for North America with eight pipeline phases and ~30 waypoint nodes.
Unlike a static dashboard, the tool is interactive by design. The view toggles between an orthographic 3D projection and a flat-map projection. The globe auto-rotates at 20fps with a pause control, and empty-space clicks toggle rotation. The sidebar lets viewers add or remove any data layer independently, so the same tool reads as a strategic planetary view, a focused regional network, or a single-layer thematic map depending on how it’s configured. A separate companion map handles the ground layer: 2000-marker viewport-based rendering across 182,218 USGS Mineral Resources records deployed locally, not in this repo.

# How this was built

I built this iteratively with Claude across multiple sessions over a 3 month period. I don’t have a formal coding background (my BA is in Geography and my day-to-day work is in sanctions and regulatory data analysis), so the approach was one component at a time rather than monolithic generation. Each new layer (weather, earthquakes, hurricanes, mines, pipelines, the flat-map toggle, the sidebar controls) was its own cycle of data model, fetch logic, rendering, then styling. It serves as a visualization of my deep interest in the mining industry, water infrastructure, and unstructured exploration of Claude’s capabilities.
When things broke, I’d make Claude explain what each function was doing before suggesting fixes. One case: quake markers were being removed from the DOM because they shared the .mk class with network nodes; a D3 join collision I spent several hours getting explained before patching, because understanding why it broke mattered more than having working code I couldn’t maintain. I also had Claude produce summary descriptions on the pertinent attributes of each node within the network, and show me how to edit these site summaries in Visual Studio Code. For the companion map’s data layer, I directed Claude to produce the Python preprocessing that converted the 182,218-record MRDS CSV from the United States Geological Survey into something the map could render fast enough to feel live.
The result is a working artifact rather than a demo, and something I use rather than something I built as an exercise.
